## 1. What Harbor is, in one paragraph

A self-hosted application manager ("a private cloud for humans", Umbrel/HexOS-like but simpler): one
Ubuntu 24.04 / Debian 12+ x86-64 machine (derivatives via `bootstrap --force`, decision 113), one administrator, apps installed from a catalog of data-only packages
(manifest + Compose subset pinned by image digest), a React console with a launcher home screen, and
three ways to reach apps: loopback (always), LAN mode (`http://harbor.local`, opt-in at install),
Tailscale tailnet, and public HTTPS via Caddy + Let's Encrypt. Everything a user can do in the console
is also a `harbor` CLI command against the same local API. Owner/user: Carlos (operator@example.invalid).

Cert access: `tls/` is 0750, server cert/key 0640 (group-readable by `harbor`), CA key stays 0600;
bootstrap adds the `caddy` user to the `harbor` group and makes the state dir group-traversable
(0710). Fixes `ERR_SSL_PROTOCOL_ERROR` on `https://harbor.local` when Caddy owns 443. Schema
validated live against Caddy v2.11.4.

## 8. Gotchas learned the hard way (do not rediscover)

- `harbor.service` has `UMask=0077`: `mkdirSync(dir, { mode })` is masked, so a dir another user must read (Caddy and `tls/`) needs an explicit `chmodSync` (decision 148). Re-sending a config Caddy rejects every minute wedged Caddy 2.10's admin API and every site behind it (certmagic panic); recovery is `systemctl restart caddy` (`--resume` loads the last good autosave).
- mDNS / `harbor.local` (decision 107): avahi publishes the host name on EVERY up interface, so once an app runs, Docker's `docker0`/`br-*` addresses (172.17.0.1…) ride along in the answer and macOS resolves nothing — pin `allow-interfaces=` to the default-route interface (bootstrap does). `systemctl restart avahi-daemon` alone (socket unit left running) can leave avahi answering legacy unicast queries (`dig @224.0.0.251 -p 5353 name +short` works) but NOT standard port-5353 queries (every real client fails): restart `avahi-daemon.socket avahi-daemon.service` together. Diagnosing from a Mac without sudo: `dig @224.0.0.251 -p 5353` proves the wire, `python3 -c 'import socket; socket.getaddrinfo(...)'` proves the resolver, a plain UDP socket bound to 5353 with SO_REUSEPORT does NOT see external packets (mDNSResponder takes them), a listener on a private group (239.x) proves multicast delivery, and `tcpdump -p` (no promiscuous mode) on the box proves what its kernel really receives. `tcpdump` on the SENDING host shows `bad udp cksum` for its own packets (checksum offload) — not a fault. `avahi-daemon -f` means `--file`, foreground is the default. Tailscale with `Use Tailscale DNS` on does NOT capture `.local` (it only routes `ts.net`) — check `tailscale dns status` before blaming it. macOS's mDNSResponder keeps state for days; a Wi-Fi toggle or `sudo launchctl kickstart -k system/com.apple.mDNSResponder` resets it.
- fscrypt (decision 103): `fscrypt status <dir>` needs ROOT (policy files under `/.fscrypt/policies` are 0600) — the daemon never calls it; it probes the kernel with a mkdir inside `<home>/volumes` (ENOKEY ⇒ locked; Node reports it as `Unknown system error -126`, errno -126, no `ENOKEY` code). `fscrypt encrypt` refuses a non-empty dir (hence seal-empty + `cp -a -T` for migrations); `fscrypt unlock` exits 1 with *already unlocked* when idempotent (check status first); `fscrypt lock` exits 1 with *incompletely locked* while any file is open (stop the app first; status then reads `Unlocked: Partially`). Ubuntu 24.04 cloud roots ship ext4 WITHOUT the `encrypt` feature: `tune2fs -O encrypt` on the mounted root works and takes effect immediately (verified, no reboot). `systemctl start <unit>` WITHOUT `--no-block` blocks until the oneshot finishes and returns its exit code — polkit's `manage-units` rule allows the verb either way, so that is how the daemon gets synchronous hard failures. Pass secrets to a root oneshot through a FIFO the daemon creates (`mkfifo -m 600`; open write side with `O_NONBLOCK`, retry on ENXIO until the root side opens for reading) — never a temp file.
- `tailscale logout` wipes tailscaled prefs including `--operator=harbor`; fixed via root oneshot + polkit (decision 64). `tailscale up` demands all non-default flags be mentioned → pass `--ssh=false --operator=harbor` and retry with the CLI's suggested flags; the login URL can take seconds → stream output, fall back to `status --json`'s `AuthURL`.
- Reddit blocks anonymous `.json` (403) since May 2026 → Reddit source needs the user's own "script" app credentials; Bing and Wikimedia work keyless. Wikimedia only serves standard thumbnail widths (use 1920px).
- Node `fetch()` drops a custom `Host` header; use `node:http` in tests that need one.
- Plain-http LAN origins are not secure contexts: no `crypto.randomUUID`, no `navigator.clipboard` (fallbacks exist in `web/src/api.ts`, `components.tsx`).
- Caddy (public proxy) owns ports 80 AND 443 → the LAN console is a Caddy route (`harbor_lan` server on :80) reconciled by the observer, and LAN HTTPS is served THROUGH Caddy too (the LAN hostnames are a route on the same :443 `harbor` server, pinned to the Harbor cert, decision 110); the daemon's direct :80/:443 listeners are fallbacks when Caddy is absent. Caddy's stock config used to squat :80 until the first exposure; the observer now reconciles at startup. Caddy runs as user `caddy`, which bootstrap adds to the `harbor` group so it can read the 0640 server cert/key under `<stateDir>/tls` (the CA key stays 0600); the state dir is 0710 (group-traverse) so Caddy can reach `tls/`.
- Operator-provided secrets (decision 125) never go into a plan: they ride `POST /v1/operations` `secrets`, are checked in `submit()` and taken by the runner at the very start of `execute()` (`takeOperatorSecrets`). A daemon restart in between loses them on purpose. Link networks (decision 126) are created by the runner, not Compose (`external: true` in both projects); `renderAndValidate` re-creates a missing one and `upAndRecord` re-attaches the other side live — Compose only ever attaches its own side.
- Several public rows per endpoint (decision 127, schema v10): never look an exposure up by `(instance, endpoint, via)` alone for `public` — pass the hostname (`repo.exposureFor(..., hostname)`), and get the main name through `mainPublicExposure(exposures, endpointId, inst.primaryHost)` (null = first published; `repo.exposures()` orders by `created_at, rowid` for that reason).
- Tailnet ports (decision 133): a tailnet exposure's `port` is its OWN port, not the endpoint's `hostPort`; the serve target is always `127.0.0.1:<hostPort>`. Never derive one from the other. Remembered addresses of a removed app live in the `exposures.retained` setting, not in `exposures` rows (decision 134).
- Exposure reachability (decision 128): never call `ctx.verify(exposureUrl(e))` directly — use `exposureCheck(e, manifest.health)` (`src/exposure/urls.ts`) so an API-only app is probed at its health path, not `/` (a 404 there is not "unreachable"). The stored/shown URL stays the root.
- A pinned `host-name=` in `/etc/avahi/avahi-daemon.conf` outlives `hostnamectl` (decision 129): `bootstrap --hostname` comments it out; a manual rename needs the same.
- Commander: an option named `--version` collides with the global version flag (that is why the root apply step uses `--to`).
- `pnpm package | head` SIGPIPE leaves a stale archive; always `| tail`.
- App catalog (decision 158): `pnpm dev`, the integration harness and e2e use `tests/fixtures/catalog` — the 9-app FROZEN fixture set, not the store. `HARBOR_DEV_CATALOG=../harbor-apps/apps pnpm dev` shows all 17. Dev, tests and openapi generation set `catalog.url: null` (never fetch; the Store says "Catalog updates are off"). `HARBOR_DEV_CATALOG_URL=<url> pnpm dev` turns checks on; the MAIN e2e daemon uses `http://127.0.0.1:9/` (the fake-mode demo fetcher answers 404, so *Check for new apps* fails and the Store shows the error), the setup daemon keeps `null` and its spec checks the off line. `pnpm dev:ui` previews `?catalog=off|error|new`. VM suite + qualification pin the box to the seed (`catalog.url: null`, `/var/lib/harbor/catalog` removed) right after bootstrap. Do not refresh the fixtures from harbor-apps: tests pin their exact content.
- The two repos (decision 161): harbor-apps CI uses PUBLISHED Harbor releases only — the latest one validates every app and bundles, and each declared `release.minHarbor` must be a release (`v<x.y.z>`, not draft/prerelease, tag commit on Harbor's `main`) whose own `catalog:verify` passes on the apps declaring it (`pnpm catalog:plan` gives the groups; `pnpm catalog:plan` exists from 0.28.2, and the published 0.28.1 (598c7f2) lacks it, so the harbor-apps CI fails at its plan step, with a message saying so, until 0.28.2 is released and latest: release Harbor first, then push harbor-apps). harbor-apps checks out each Harbor release at its resolved commit with that commit's own Node (engines) and pnpm (`packageManager`), bundles in a read-only job and publishes from a separate write job. `.harbor-ref` is gone. Harbor's release job (`pnpm package`) still needs a published harbor-apps release. `pnpm catalog:plan` prints pnpm's own `> harbor@… catalog:plan` header on stdout too unless run as `pnpm -s catalog:plan` (or `tsx scripts/catalog-plan.ts`); the JSON is one line, the last one.
- Catalog serials: a harbor-apps commit with the same committer second as an existing release fails publish ("make a new commit"; a re-run of the released commit just skips); a committer time more than 5 minutes ahead fails the release job; a commit not newer than the latest release skips when main has moved on and fails as clock skew when it is still main's tip. harbor-apps CI is two jobs (verify → release); only `release` has `contents: write`, and `GH_TOKEN` is set only on its two `gh` steps. `releases/latest/download` can race a new release between the `catalog.json` and `catalog.zip` fetch: the daemon starts a check that sees a zip/`catalog.json` mismatch over once (`pnpm package` avoids the race by resolving the `c<N>` tag first). A downloaded folder counts only while its stored `catalog.json` parses and names its folder's serial (an integrity re-check cached by size/mtime, not a trust check; else the seed, warned once); a serial > 24 h ahead of the clock is refused, so test serials must stay in the past (the fixtures use 1_76x/1_77x/1_780_000_000). A plan whose revision/hashes moved before apply fails `PLAN_STALE` (app state kept, no notification, stale install row purged). `pnpm package` does not race: it resolves `releases/latest` to `c<serial>` once (redirect `Location`) and fetches both files from `releases/download/c<serial>/`.
- `harbor catalog status` shows "Not checked since the daemon started" after every restart: `checkedAt`/`error` live in memory only.
- restic (decision 149, verified with 0.19.1): exit 10 = no repository, 12 = wrong password, 11 = locked, 3 = snapshot made with unreadable files, 130 = interrupted. `restore <id>:<subfolder> --target X` puts the subfolder's CONTENTS into X (that is how a restore lands directly in a sealed `volumes/`). restic picks the parent snapshot by host + exact paths, so the per-app stage path must stay stable (`/run/harbor-backup/stage/<app>/<place>`) or every pass rescans everything. `forget --group-by ''` + `--tag app:<id>,kind:cold` (comma = AND) applies retention per app. Secrets never in argv (`/proc/<pid>/cmdline` is world-readable): `RESTIC_PASSWORD`/S3 keys in env, ssh key + known_hosts in tmpfs files, rclone passwords obscured into a root-only rclone.conf.
- Decision 164: on `http:` the console fetches the open `GET /v1/setup`, loads `https://<same host>/v1/network/https/probe` as an IMAGE (the CSP `img-src` lists exactly the cert hosts via `uiCsp()`) and `location.replace`s to https only when it loads; `?skiphttps` keeps a tab on http (sessionStorage). A locked machine key is `MACHINE_KEY_LOCKED` (not `INVALID_STATE`); `POST /v1/account/unlock` fixes it without a re-login, and its wrong-password error is 422 on purpose (a 401 logs the console out). Pure web helpers that unit tests import must have NO relative imports and no DOM (see `web/src/app/https-target.ts`): the node tsconfig typechecks them.
- GPU (decision 179): host facts come from `ctx.gpu` (`src/system/gpu.ts`), never from the planner; fake mode has no card unless `HARBOR_DEV_GPU=nvidia|dri|dri-toolkit-missing|toolkit-missing|restart-needed|driver-missing|reboot-needed|driver-too-old` (e2e sets `nvidia`, driver 595.99.02); the console mock takes `?gpu=<same names>`. Driver checks (decision 181) are read-only and run before the toolkit checks: never add an install/update step for drivers. Only operations that re-render the runtime file pick up a newly installed NVIDIA toolkit — **Restart** does, Start after Stop does not (`compose start` reuses containers). harbor-old's `/dev/dri/renderD128` belongs to the NVIDIA card (nvidia-drm) and is ignored on purpose.
- App settings (decision 180): values are NOT secrets (plans, DTOs, events, logs) and only overrides live in `instances/<id>/settings.json` (no DB column); every `renderAndValidate` reads it, so anything that re-renders keeps the values. Install/update values ride the submission (`POST /v1/operations` `settings`, held in memory by plan id like operator secrets); configure values are in the plan request. A stored value the installed release no longer allows is ignored at render and pruned by the next update. `tests/integration/settings.test.ts` is the Harbor-settings test (older); the app-settings tests are `app-settings.test.ts`. Never name an e2e app with a word a nav link uses ("Settings E2E" broke `getByRole('link', { name: 'Settings' })` in later tests).
- Never test on .192 (production `harbor`): live tests go to harbor-old (.146) or the droplet.
- xterm.js needs `style-src 'unsafe-inline'`; the WebSocket terminal authenticates by first message, never URL.
- macOS has no `timeout`; use `curl --max-time` or `gtimeout`.
- The e2e drag test needed slot-based hit testing (rapid pointer events outrun React renders) and synchronous order tracking.
- Upgrading an unclaimed machine (no admin) must not demand a password: bootstrap keeps setup mode.
- DigitalOcean droplets do not share a broadcast domain: mDNS cross-host resolution cannot be tested there (only local `getent hosts harbor.local`).
- The operation queue (decision 183, docs/design/QUEUE.md): `instances.active_operation_id` = the app's FIRST unfinished operation and moves along the chain via `repo.syncActiveOperation` at every transition; never set it to NULL by hand while items wait. Run order is `operations.seq`, not `created_at`. `started_at` = picked by the runner; nothing was done while `state='queued'` (the runner moves to `applying`/`preparing` right before a kind's first step); a person may cancel only items not yet picked; restart, shutdown and a person's cancel all go through `service.cancelNeverRun`. A queued action has `plan_id NULL` until its turn. Final states are `succeeded|failed|needs_action|cancelled`: any new poll loop must stop on `cancelled` too. Harbor's own actor names live in `INTERNAL_ACTORS` (`src/contracts/api.ts`): a new background actor goes there, or its items become cancellable and its successes pile up in the tray. e2e slow operations: `HARBOR_DEV_FAKE_CONTROL` (dev.ts only) `{hold: true, match}` holds a fake pull until the file changes; e2e `trayDone` waits by operation id, so call `login()` on the page first.

- VPN and offline apps (decision 184): **Docker 29's embedded resolver forwards external lookups from the HOST's network namespace** (source = the host's LAN address; nothing crosses the app's bridge), so a subnet-based mark never sees an app's DNS; that is why non-direct apps get a rendered `dns:` (VPN `198.51.100.53` → marked on the output path and DNAT-ed into the tunnel; offline `127.0.53.53`, refused locally). Test DNS from INSIDE the app's container (a throwaway `docker run --network <app net>` probe has Docker's default resolver, not the app's). **`nft -f -` from a pipe fails on nft 1.0.9** ("Not a regular file: /dev/stdin") although `nft -c -f -` over ssh passed: load from a file. Kernel state (ip rules, table 4842, `hb-vpn0`) is gone after a reboot; `harbor-egress.service` (nft) runs before Docker and `harbor-vpn.service` brings the tunnel back after network-online. The every-app switch restarts moved apps (actor `vpn-policy`); a start re-creates containers whose rendered resolver no longer matches.
