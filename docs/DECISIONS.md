# Decision log

Small technical decisions made during the autonomous build, in the order they were taken. Product
scope and behaviour come from [TDD.md](../TDD.md); these are the implementation calls it left open.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-09-14 | **Live test target is a DigitalOcean droplet** (`harbor-test`, Ubuntu 24.04 x64, s-4vcpu-8gb) controlled by `scripts/vm/do-vm.mjs`, instead of a local Vagrant VM. The `Vagrantfile` is still generated. | The build host is Apple Silicon: x86-64 guests only run under slow QEMU emulation, and Vagrant needs an admin password to install. The user offered and authorized the droplet. Rebuild = `vagrant destroy && up`; power-cycle = reboot test. |
| 2 | 2026-09-14 | Local Docker Desktop (arm64) is used **only** for the developer loop (Compose canonical validation and labelled install/remove tests), explicitly authorized by the user. Bootstrap, systemd, tools and reboot tests run only on the VM. | Faster iteration; the docs forbid using an incidental Docker host as *evidence*, not as a dev tool when authorized. |
| 3 | 2026-09-14 | TypeScript **5.9** (not 7.x), `@types/node` 24, Fastify 5, Vitest 5, Vite 8, React 19, better-sqlite3 13, dockerode 5, commander 15, yaml 2.9, Ajv 8 (2020-12 class). Exact versions pinned by `pnpm-lock.yaml`. | TS 7 (native port) is too new for typescript-eslint; everything else is the current stable line. |
| 4 | 2026-09-14 | Image references pin the **multi-arch index digest** (what `docker pull` reports) and record the linux/amd64 platform manifest digest separately in `release.json` (`platformDigest`). | Compose resolves `repo@index-digest` on any platform; the amd64 manifest digest documents exactly which bytes were qualified. |
| 5 | 2026-09-14 | Excalidraw provenance tag is `latest` (upstream publishes only `latest` and `sha-<commit>` tags); identity is the digest. Recorded image creation time 2026-05-06. | No version tags exist upstream; the digest is immutable and sufficient. |
| 6 | 2026-09-14 | **n8n pinned to 2.38.7** — the version the upstream `stable` tag resolved to on 2026-09-14 (2.39.5 was published the same morning). PostgreSQL **16.15** (latest 16.x). Portainer CE **2.39.7** (latest explicit 2.39.x version tag). | Follow upstream's recommended `stable` channel rather than a same-day release; 16.x baseline required by TDD; explicit version tag preferred over the floating `lts` tag. |
| 7 | 2026-09-14 | Catalog `availability` reflects package *validity*; `qualification` (passed/blocked/pending) is a separate field. | Otherwise nothing could be installed before the live qualification run; the UI/CLI still show the qualification state honestly. |
| 8 | 2026-09-14 | Ajv is configured with `coerceTypes:false`, `useDefaults:false`, `removeAdditional:false`, `strictTuples:false`. Healthcheck `test` uses `prefixItems:[{const:'CMD'}]` + `items:string`. | No silent coercion (TDD 4.2). `strictTuples` only silences Ajv's tuple-length heuristic, which conflicts with "CMD followed by N args". |
| 9 | 2026-09-14 | Literal `$` in package strings is allowed only when it cannot start an interpolation (`$` not followed by `{`, a letter, `_` or `$`); the renderer escapes every `$` as `$$` in generated Compose. Both `docker compose config` (real) and the fake runner apply interpolation semantics to the generated file. | TDD requires rejecting interpolation while rendering literal dollars correctly. |
| 10 | 2026-09-14 | Singleton lock = lock file with PID + liveness check (`kill(pid,0)`), stale locks reclaimed. | Node has no portable `flock`; the daemon and maintenance commands are the only writers. |
| 11 | 2026-09-14 | Port allocation: pure lowest-free selection over {stored claims ∪ active/queued claims ∪ Docker published ports ∪ management port}, then a real `127.0.0.1` bind probe per candidate; ports with a listener are excluded and allocation retried. Submission re-checks claims in the same SQLite transaction (`port_claims` PK). | Matches TDD "plans may propose the same port; submission atomically claims it". The bind probe on Linux also detects `0.0.0.0`/`::` listeners. |
| 12 | 2026-09-14 | Operation phases are persisted before side effects; on daemon start every `queued/applying/verifying` operation becomes `needs_action` and its instance `needs_action` with generation bumped. No replay. | TDD section 6. |
| 13 | 2026-09-14 | Instance directory layout `<state>/instances/<uuid>/{release,runtime,secrets}` (0700/0600). Secrets are 32-byte hex files written once with `O_EXCL` + fsync. Runtime `compose.yaml` holds plaintext env (documented trusted-preview trade-off). | TDD section 9. |
| 14 | 2026-09-14 | `compose up` flags: `--detach --no-build --pull never --quiet-pull --wait --wait-timeout N`. Never `--remove-orphans`, `--renew-anon-volumes`, `--force-recreate`. Pull is a separate phase with its own timeout (`--policy missing`). Spawn env is scrubbed: fixed PATH, private `DOCKER_CONFIG`/`HOME`, explicit `DOCKER_HOST`. | TDD render rule 6 and execution boundaries. |
| 15 | 2026-09-14 | Fake adapter interprets the *generated* compose file and runs real loopback HTTP listeners on the published ports. | Readiness, port conflicts and UI tests exercise the real code path without Docker. |
| 16 | 2026-09-14 | Static UI served with a strict CSP (`default-src 'self'`, `frame-ancestors 'none'`); API rejects unknown `Host`, any non-local `Origin`, cross-site `Sec-Fetch-Site`, and non-JSON bodies on `/v1` mutations. No CORS headers at all. | TDD sections 7–8. |
| 17 | 2026-09-14 | `remove` deletes only recorded containers (after label check) and the owned default network if empty; the observer never mutates. `start` uses `compose start` on the stored runtime file after verifying volumes/secrets/containers. `stop` stops recorded containers by ID. | TDD "Other operations". |
| 18 | 2026-09-14 | `InstanceSummary.operationId` = active operation if any, else the last finished one. `hasRetainedData` = everInstalled or has secrets. | Lets the UI show progress and a Remove/Reinstall affordance from one field. |
| 19 | 2026-09-14 | Compose CLI plugin discovery: the scrubbed `DOCKER_CONFIG` holds only `cliPluginsExtraDirs` (config `docker.cliPluginDirs`). Empty on Ubuntu (system plugin dir); `~/.docker/cli-plugins` for the Docker Desktop dev loop. | Found by the live Docker test: with an empty private config the CLI could not find `docker-compose` on macOS. |
| 20 | 2026-09-14 | A reinstall that fails before creating containers returns the instance to `retained`; one that created containers becomes `failed`. Install failures are `failed`; start/stop/remove failures are `needs_action`. | Otherwise a blocked reinstall (DATA_MISSING) left the instance stuck in `needs_action` with no path to retry after restoring data. |
| 21 | 2026-09-14 | Daemon shutdown during an operation throws an internal interruption and leaves the operation in flight; the next start marks it `needs_action`. The daemon waits up to 20 s for the runner, then exits. | Honest state after `systemctl restart`; matches TDD "do not replay". |
| 22 | 2026-09-14 | Browser exports in the live suite disable the File System Access API (`showSaveFilePicker`) via an init script so Excalidraw/BentoPDF fall back to downloads that Playwright can capture. | Headless Chromium exposes the picker API but cannot show a dialog; the apps prefer it when present. |
| 23 | 2026-09-14 | n8n live demo: owner setup through the real form; credential/workflow/execution through n8n's REST endpoints called as in-page `fetch` (the browser sends the `Secure` cookie on `http://localhost`); the credentialed target is a test-owned listener on the instance network's gateway IP. | Playwright's request API does not send Secure cookies over plain HTTP; a gateway-bound fixture is reachable from the container without touching Harbor's network. |
| 24 | 2026-09-14 | Package telemetry: `N8N_DIAGNOSTICS_ENABLED=false`, `N8N_VERSION_NOTIFICATIONS_ENABLED=false` added to the n8n package. | A local self-hosted preview should not phone home; upstream defaults otherwise unchanged. |
| 25 | 2026-09-14 | Portainer `installed` vs `setup_required` decided by its `/api/users/admin/check` (204 vs 404) during tool observation; Cockpit is `installed` when its socket answers (OS accounts, no first-run). | Real onboarding state instead of a hardcoded healthy card. |
| 26 | 2026-09-14 | The live suite pre-installs Cockpit on the fresh VM before bootstrap so `--with-tools` exercises the "bind existing tool without reconfiguring" path; the managed Cockpit path is evidenced by the first manual bootstrap log. Portainer is always the managed path. | Both tool paths get real evidence in one VM lifecycle. |
| 27 | 2026-09-14 | `pnpm package` archives with bsdtar `--no-xattrs --no-mac-metadata --uid 0 --gid 0`; contents sorted; SHA256SUMS written. Reproducible modulo file mtimes (documented). | GNU tar on Ubuntu warned about macOS xattr headers in the first archive. |
| 28 | 2026-09-14 | `harbor.service` uses `Wants=docker.service` (plus `After=`), not `Requires=`. | Live A10 showed that with `Requires`, `systemctl stop docker` also stopped Harbor, so the UI could not report Docker as unavailable. Harbor must stay up and show `unavailable`/`unknown`. |
| 29 | 2026-09-14 | The live suite forwards 18080–18099 (not only the Vagrantfile's 18080–18085) because retained instances keep their port allocations and the demo consumes seven ports. | Run 4 could not reach n8n on 18086 through the tunnel; the Vagrantfile subset stays small as the TDD asks, the suite documents its own wider set. |
| 30 | 2026-09-14 | Portainer CE 2.39's first-admin form requires a one-time setup token printed to the container log, and the instance locks itself 5 minutes after start. Harbor keeps this upstream protection (no `--no-setup-token`) and documents it in the tool card note, the operator guide and the live suite (which restarts the container for a fresh window and reads the token). | Live A14 found the "Create user" button disabled until the token is supplied; disabling the protection would weaken a Docker-socket-bearing console. |
| 31 | 2026-09-14 | In `--json` mode the CLI prints exactly one document for a failed operation (the operation itself) and exits with the error category; the error body is not printed a second time. | Live A12's negative case produced two JSON documents on stdout, which no consumer can parse. |
| 32 | 2026-09-14 | Exposure model (docs/design/EXPOSURE.md): `exposures` table, per-instance `primary_exposure`, plan kinds `expose`/`unexpose`/`reconfigure` through the same queue. Providers are host services: Tailscale (`tailscale serve --https=<same port>`) and Caddy (admin API on 127.0.0.1:2019, full JSON config reconciled from state, `--resume` for persistence). No package hooks. | Carlos's direction (NPM + Tailscale as canonical paths); Caddy chosen over NPM for a documented admin API and automatic TLS. |
| 33 | 2026-09-14 | Public exposures default to basic-auth protection when the package has no `setup` block (no login of its own); credentials are a retained instance secret shown once in the operation result. bcrypt (bcryptjs) hashes go to Caddy, never the plaintext. | Excalidraw/BentoPDF would otherwise be open to anyone who reaches the hostname. |
| 34 | 2026-09-14 | Tailnet exposures use the same port number as loopback and no auth layer (tailnet ACLs govern access). The Harbor UI can be exposed on the tailnet at :443 (`tailscale serve` → management port) and the daemon's Host/Origin allow-list follows that record; public exposure of the UI is refused by the API schema. | "Same port, three addresses" keeps the mental model simple; the UI must never be public. |
| 35 | 2026-09-14 | Failed exposure operations leave the instance's install state unchanged (the app is unaffected); exposures have their own `pending/active/degraded` states re-checked by the observer with real certificate verification. | Honest state without conflating app health and address reachability. |
| 36 | 2026-09-14 | Schema v2 with an in-place migration from v1 (exposures table, `primary_exposure` column, plans `kind` CHECK dropped by table rebuild with foreign keys temporarily off). | The MVP installation on the droplet must upgrade without data loss. |
| 37 | 2026-09-14 | Console rewrite (docs/design/UI.md): Home launcher with system strip, App Store from package `presentation` metadata, Publishing, Platform and Settings pages; hash router, plain CSS tokens, dark by default; operation tray bottom-right. Same API, no new engine paths. | Carlos: "like Umbrel and/or HexOS but better and easier". |
| 38 | 2026-09-14 | `GET /v1/catalog/{id}/asset/{name}` is unauthenticated (static, hash-verified catalog assets with nosniff and a sandboxed SVG CSP); every other `/v1` read stays behind the bearer token. | `<img src>` cannot carry a bearer token; the icons are not sensitive. Same-origin/Host guards still apply. |
| 39 | 2026-09-14 | External storage ("bring your own folder", docs/design/CATALOG.md section 3): optional per storage claim, validated at plan time (absolute, normalized, denylist incl. symlink targets, exists, no overlap across instances), rendered as a bind mount with `create_host_path: false`, recorded as a `bind` resource, verified on reinstall/start, never created/chowned/deleted by Harbor. Schema v3 widens `resources.kind`. | The biggest pain of Immich/Nextcloud/Jellyfin is where the big data lives; managed volumes remain the default so one-click stays one-click. |
| 40 | 2026-09-14 | `configuration[].format` (`url`, `origin`, `authority`, `host`, `scheme`) selects the part of the primary URL a variable receives; environment keys may be mixed case. | Nextcloud/Forgejo/Vaultwarden/Jellyfin want different shapes of their own address; upstream variable names are not all upper case. |
| 41 | 2026-09-14 | Catalog round 1 selection (docs/design/CATALOG.md section 1): Compose-subset fit, browser-only first run, telemetry off, health path before accounts exist. OpenClaw, Paperless-ngx, Linkding, a separate Collabora and host-network apps are documented as out for now with the exact unlock. | A one-click promise must not depend on hidden CLI steps or printed secrets; the exclusions are honest, not accidental. |
| 42 | 2026-09-14 | Nextcloud Office is delivered through Nextcloud's own "recommended apps" (richdocuments + built-in CODE server) rather than a Collabora container. | The built-in server works on loopback http and on published https alike; a separate Collabora needs scheme-dependent `ssl.termination` settings that the manifest cannot express yet. |
| 43 | 2026-09-14 | Image pinning is an editorial script (`scripts/catalog-pin.mjs`: registry API, index digest in compose, platform digest and image config facts in release.json); qualification is a live script (`scripts/vm/qualify-catalog.mjs`) that writes `passed`/`blocked` with evidence. Runtime only verifies. | Same provenance discipline as the MVP packages, at catalog scale. |
| 44 | 2026-09-14 | Console polish for non-technical users: greeting and one-line status on Home, "popular picks" when no app is installed, app display names on tiles, meters coloured by pressure (Docker shown as a status, not a bar), plan review leads with a human sentence and a small facts list (address, data, secrets) with the exact steps collapsed, the operation tray speaks in sentences ("Memos is ready") and offers Open plus the app's own next step, theme choice (device/dark/light) remembered per browser. | Carlos: "make it super nice for user". Every technical detail stays one click away; nothing was removed from the API or the plan. |
| 45 | 2026-09-15 | Bootstrap passes a Tailscale auth key to `tailscale up` through a root-only temporary file (`--auth-key=file:`), never as an argument or in logs; and a failing optional tool step (Tailscale, Caddy, Cockpit, Portainer) can no longer leave Harbor down: the daemon is (re)started first and the tool error is rethrown afterwards. | Live run 12 with Carlos's real key: the CLI does not understand an `env:` prefix and treated the literal string as the key ("unable to validate API key"), and the failure left the daemon stopped after the release update. | 46 | 2026-09-15 | Self-service Settings for non-technical operators (docs/design/UI.md §7): change password (`PUT /v1/account/password`, revokes other sessions), remote access (Tailscale login by browser URL or auth key, logout, Harbor-on-tailnet toggle; `POST /v1/platform-tools/tailscale/login|logout` run `tailscale up/logout` as the operator user), storage overview (`GET /v1/host/storage`: disks from /proc/mounts filtered to real filesystems, the Harbor data folder, folders in use by apps) and a folder picker (`GET/POST /v1/host/folders`).
