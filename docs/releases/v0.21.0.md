## Harbor 0.21.0 — values you provide, and apps that talk to each other

Everything in the [0.19.1 beta notes](https://github.com/carlosalaniz/harbor/blob/main/docs/releases/v0.19.1.md)
still applies. New in this release:

- **Apps can ask you for a value at install** (decision 125): another service's access token, an
  SMTP password. The install review shows a password field; the value is kept like the secrets Harbor
  generates and never shown again (not in the console, API, plans or logs). Change it later on the
  app's page. CLI: `--secret <id>=@file` or `<id>=-` (stdin).
- **App links** (decision 126): an app that needs another app asks which one at install; Harbor gives
  the two a private network that only the asking app and the other app's one service join (never its
  database), and hands the app an address like `http://docs-link:3010`. Settings → Internal networks
  lists every link; removing the providing app flags the other one *needs a provider*. CLI:
  `--link <id>=<app>`, `harbor configure`, `harbor links`.
- State schema v9 (a `links` table); the upgrade migrates in place.

Package authors: `docs/DEVELOPER_PACKAGES.md` §2 (template) and §8.

Already running Harbor? Settings → Overview → Update.
