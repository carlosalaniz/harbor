# Harbor 0.50.0

**Apps from private git repositories.**

- **+ Your own app → Git repository** has an **Access token** field. Give a token that can read the repository and
  Harbor adds it like a public one: it builds the app, checks the branch for new commits and redeploys on commit.
  From a terminal: `harbor sources add <url> --token-stdin < token.txt` (the token is read from stdin, never typed
  on the command line).
- For GitHub, make a *fine-grained personal access token* for that one repository with **Contents: read-only**.
- Harbor keeps the token encrypted with this machine's key and never shows it again. *Your repositories* only says
  *private (token stored)*.
- When a token expires or is revoked, Harbor says *the repository refused the token*, on the source and once in
  Notifications. Replace it under **Your repositories → Token** (or `harbor sources token <app> --token-stdin`):
  Harbor tries the new one before keeping it. **Remove token** (or `--clear`) drops it; forgetting the source
  deletes it too.

**Good to know**

- After Harbor restarts, private repositories are checked again once you log in (their tokens are locked with the
  machine key until then, like backups).
- A repository URL with a token inside it (`https://user:token@…`) is refused: put the token in its own field.
- Tried against a real private GitHub repository from a Mac (no token, wrong token, right token: check, clone, read
  `harbor/`). Not yet tried end to end on an Ubuntu machine.
