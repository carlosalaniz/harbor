# Harbor 0.38.0

After a restart, encrypted apps ask for your password once instead of sitting there locked. Contributed by
[@0xDonPepe](https://github.com/0xDonPepe) (#4), found on a real home server over two reboots.

- **Lock screen after a restart.** A browser that stayed logged in now opens on a screen that asks only for your
  password when Harbor restarted (a reboot or a Harbor update) and encrypted apps or backups wait for it. The
  password unlocks them in place; your session is kept.
- **A locked app is never updated, repaired or reinstalled.** Harbor refuses at the review and asks for the
  password first. Before, an update approved in that state deleted the app's containers, could not open its data,
  and failed its rollback too.
- **Encrypted apps come back completely after the unlock.** An app with a container Docker had already restarted
  on its own (a Redis cache, for example) counted as running, so Harbor did not start the rest of it.
- **Automatic updates wait for the unlock.** An app set to update itself while it was locked used to skip that
  update for good; it now runs right after the password.

New API field: `SystemDto.unlockNeeded`. No change to the package format.
