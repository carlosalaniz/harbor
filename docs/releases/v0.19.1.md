## Harbor 0.19.1 — beta for testers

**Who this is for.** One administrator, one Ubuntu 24.04 (or Debian 12/13) x86‑64 machine you are
willing to reinstall, and a wish to run your own apps privately. Not for data you have no other
copy of: Harbor does not back up app data yet.

**Install.** `curl -fsSL https://raw.githubusercontent.com/carlosalaniz/harbor/main/install.sh | sudo bash`
then open `http://harbor.local/` (or the machine's IP) and finish the wizard with the printed
setup code. Already running Harbor? Settings → Overview → Update.

**Use 0.18.1 or newer on a fresh machine.** 0.17.5–0.18.0 picked Docker's Debian repository on
Ubuntu and failed on any machine without Docker already installed.

### What to expect

- **Every app on every address at once.** LAN (`http://harbor.local:<port>` or the IP), secure LAN
  (Settings → Network), Tailscale and your own domains. Each app has a *main address*, picked at
  install from the choices that exist, which is only what it puts in links it sends out. Apps that
  do not work over plain `http://` (n8n, Vaultwarden) need an HTTPS main address and the store says
  so before you install. Changed network settings? Open the app and press **Restart**.
- **Your own domain, three ways.** Harbor's Caddy with Let's Encrypt (ports 80/443 forwarded to the
  machine), Tailscale, or your existing reverse proxy (Nginx Proxy Manager, Traefik) via
  *Publish… → Your own proxy*.
- **Nextcloud that works on all of the above.** Harbor sets it up on first start and shows the
  `admin` password once (nobody on your network can claim the setup page), keeps its trusted
  addresses in step after every start and publish, and installs Office, Calendar and Contacts.
- **Drives that need you show up on Home.** A drive your desktop mounted where Harbor cannot write,
  or one plugged in but not mounted, gets a card with a one‑click fix (*Let Harbor manage it* /
  *Mount it*) and a bell warning linked to Settings → Storage. Dismiss hides it until it changes.
- **Folders of your own** for app data must be under `/mnt`, `/media` or `/srv/harbor`; Harbor
  refuses others up front instead of starting an app that would be stopped a second later. Drives
  with such folders keep working when moved to another Harbor machine.
- **Encrypted app homes** (since 0.17): every app installed Local or on a drive is sealed with the
  kernel's own encryption, one key per app; one Harbor recovery key (12 words, shown once) opens
  them anywhere.

### Verified on this line

- Fresh DigitalOcean droplet: the public one‑liner installs cleanly, and the 24 live acceptance
  checks on 0.19.0 give 23 pass, 0 fail, 1 not run (Tailscale, no auth key) — run
  `vm-2026-10-05T01-36-24`, `docs/VERIFICATION.md` §3e.
- Real hardware (the maintainer's Kubuntu box): Nextcloud on LAN, drive takeover from KDE, drive
  re‑plug — §3f.

### What not to trust yet

- **No backups of app data.** Keep another copy of anything you care about.
- **Headless boxes.** After a power cut or reboot, sealed apps stay locked (and down) until someone
  logs in to the console. Automatic unlock is a 1.0 item.
- **After Harbor restarts or updates, log in again before installing an encrypted app.** A
  remembered browser session still works, but Harbor refuses to seal a new app until your password
  unlocks this machine's key (it says so).
- **Not re‑checked on this exact build:** the Tailscale path, and the largest packages (Immich,
  Open WebUI + Ollama), last qualified on 0.18.2.
- **App‑generated secrets** (database passwords, the provisioned Nextcloud login) are plaintext
  under Harbor's state directory, mode 0600. See `SECURITY.md`.
- Single administrator, no multi‑user; x86‑64 only.
- The repository has no LICENSE yet: all rights reserved until 1.0.0.

**Report a problem:** run `harbor diagnostics` on the machine and paste the block into
https://github.com/carlosalaniz/harbor/issues/new?template=bug.md. It contains versions, host
facts, app states and a log tail, never secrets.
