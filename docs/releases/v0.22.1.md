## Harbor 0.22.1 — three fixes from a real host

Everything in the [0.22.0 notes](https://github.com/carlosalaniz/harbor/blob/main/docs/releases/v0.22.0.md)
still applies. Fixed in this release:

- **API-only apps no longer show `degraded` when published** (decision 128). The reachability check
  now asks for the app's own health page (for example `https://api.example.com/healthz`) instead of
  `/`, which such apps answer with 404. Both the publish step and the periodic re-check do this; other
  endpoints still check `/`. Addresses already marked `degraded` recover on the next re-check.
- **Renaming the machine renames its `.local` name too** (decision 129). `bootstrap --hostname <name>`
  now comments out an old `host-name=` pinned in `/etc/avahi/avahi-daemon.conf`, so mDNS follows the
  machine's hostname. Already renamed and still answering the old name? Run
  `sudo /opt/harbor/bin/harbor bootstrap --yes --hostname <name>` once.
- **Nextcloud Office keeps working after you change Nextcloud's main address** (Nextcloud package
  revision 4). After every start, publish and unpublish, the built-in office server is re-pointed at
  the current address, so documents open after `harbor primary nextcloud public`. A Collabora server
  of your own is left alone. Installed Nextcloud apps are offered the update in the App Store.

Already running Harbor? Settings → Overview → Update.
