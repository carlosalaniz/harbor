## Harbor 0.25.0 — move an app to another drive, keeping its encryption

Everything in the [0.24.0 notes](https://github.com/carlosalaniz/harbor/blob/main/docs/releases/v0.24.0.md)
still applies. New in this release:

- **Move an encrypted app** — app details → *Move to…*, or `harbor move <app> --location <place>`.
  Move between this machine's Harbor data folder and an ext4 drive, or from drive to drive. It stays the
  same app (name, ports, addresses, links). Its passphrase and recovery words keep working. Its data is
  never written unencrypted anywhere. The old copy is deleted only after the app has started from the
  new place; if anything fails first, it stays where it was. The app is down while its data is copied.
- Fixed: encrypting or moving an app a second time on the same disk could fail with "there is already a
  protector named …".

Coming from 0.22 or older? Read the [0.23.0](https://github.com/carlosalaniz/harbor/blob/main/docs/releases/v0.23.0.md)
and [0.24.0](https://github.com/carlosalaniz/harbor/blob/main/docs/releases/v0.24.0.md) notes too. Tailnet
addresses move to their own port once after the upgrade (a notification gives each new address). Apps
installed from the CLI before 0.23.0 are not encrypted (`harbor list` → ENCRYPTED); `harbor seal <app>`
encrypts them in place.

Already running Harbor? Settings → Overview → Update.
