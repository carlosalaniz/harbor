# Harbor 0.45.0

**Browser apps can keep their own sandbox on.**

- **New permission, *Run a web browser's own sandbox*:** an app that runs Chromium, Chrome or Firefox inside its container (Crossbar, for example) can ask for it, and you accept it in the install review like the network permissions. Without it, such an app's browser only starts with its sandbox turned off.
- What it allows: Docker's default protection stays in place apart from four calls (`clone`, `unshare`, `setns`, `chroot`) that the browser needs to create its isolated namespaces. No extra capability, no change to AppArmor.

**Package format:** new permission value `browser-sandbox` (`permissions: {<service>: [browser-sandbox]}`). First accepted by 0.45.0, so an app that uses it declares `release.minHarbor: "0.45.0"`. Any source may ask for it, including uploaded zips and git sources.
