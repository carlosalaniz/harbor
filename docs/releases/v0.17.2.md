## Harbor 0.17.2 — LAN HTTPS works when the public proxy (Caddy) is installed

**Who this is for.** Anyone running Harbor in LAN mode **and** the public proxy (Caddy) who saw
`ERR_SSL_PROTOCOL_ERROR` on `https://harbor.local` after trusting the certificate. Upgrade from the
console (Overview → Update) or reinstall with the one-liner; nothing about existing apps changes.

**Install.** `curl -fsSL https://raw.githubusercontent.com/carlosalaniz/harbor/main/install.sh | sudo bash`
then open `http://harbor.local/` (or the machine's IP) and finish the wizard with the printed
setup code. The installer takes the newest release, which is this one.

### What to expect

- **LAN HTTPS now works alongside Caddy.** When the public proxy is installed it owns port 443
  (for public hostnames), which previously stopped the daemon's own secure listener from binding —
  so `https://harbor.local` hit Caddy with no route and aborted the handshake. Now Caddy terminates
  TLS for the LAN hostnames itself using the same Harbor-minted certificate, so the padlock returns
  with no warning after the one-time trust per device.
- **No re-trust needed.** The certificate is unchanged; if you already trusted the Harbor CA on a
  device, `https://harbor.local` just works again.
- Public hostnames (via Caddy + Let's Encrypt) and LAN HTTPS coexist on the same port.

### What not to trust yet

- Same list as 0.17.0/0.17.1 (headless boxes stay locked until login, app-generated secrets are
  plaintext under the state dir, no backups, no multi-user, no ARM builds).
- The repository has no LICENSE yet: all rights reserved until 1.0.0.

**Report a problem:** run `harbor diagnostics` on the machine and paste the block into
https://github.com/carlosalaniz/harbor/issues/new?template=bug.md. It contains versions, host
facts, app states and a log tail, never secrets.
